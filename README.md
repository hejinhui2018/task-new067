# 直播导播流程单（Rundown Console）

面向直播导播团队的节目流程单，支持**双场地联排**：主舞台与访谈间两条时间线独立调整，
嘉宾、主持人、转播车等共享资源统一校验。临时延长采访、插入内容时，立即看到两条时间线如何变化；
固定开播点绝不被悄悄越过——超时先由缓冲段和可压缩环节消化，消化不下就明确报出冲突；
资源撞车时给出冲突区间、涉及环节和经过模拟验证的调整建议，绝不简单把后续内容一起顺延。

技术栈：React 18 + TypeScript + Vite，无后端，数据保存在浏览器 localStorage。

## 运行方式

要求 Node.js ≥ 18。

```bash
npm install        # 安装依赖
npm run dev        # 开发预览（默认 http://localhost:5173）
npm test           # 运行调度引擎与撤销/重做测试（vitest）
npm run build      # 类型检查（tsc --noEmit）+ 生产构建（输出 dist/）
npm run preview    # 预览生产构建
```

## 调度规则

1. **整体顺延**：普通调整（改时长、拖动排序、插入/删除）后，每个环节紧跟前一环节——
   只影响本场地，另一场地不受波及。
2. **固定点保护**：固定环节之前的超时，按顺序消化——
   先扣「上一个固定点（或开播）到本固定点之间」的**缓冲段**，
   再按流程顺序压缩**可压缩环节**（压到各自下限为止）。
   消化只发生在本场地同一区段内，不会跨固定点倒灌，更不会跨场地。
3. **冲突上报**：消化能力耗尽仍放不下 → 红色冲突横幅，标明超时量、已消化量、
   仍超出量与涉及环节。固定点仍在原时刻开播，系统绝不悄悄后移。
4. **空档**：固定点前内容不足时留出空档行（可点击 ＋ 插入内容），固定点依然准点。
5. **共享资源统一校验**：同一资源（嘉宾、主持人、转播车……）在不同场地的排程区间
   不得重叠。撞车时红色横幅给出**冲突区间**与**涉及环节**，并提供**可行调整建议**
   （缩短先占用方 / 在后占用方前插垫片 / 换到另一场地排在对方之后）。
   每条建议都先在整档状态上模拟验证：应用后必须消除该冲突，且不新增固定点冲突或
   其他资源冲突，否则不会出现在建议里。全部不可行时明确提示人工处理（无解场景）。
6. **已执行前缀**：预演到任意时刻后可「锁定已执行前缀」。已执行的环节不可修改、
   删除、移动，也不再参与超时消化（已播出的内容不能改写）——消化不下就按规则 3 报冲突。

计划时长是唯一的源数据；压缩量、开始/结束时间、冲突全部由引擎实时推导，
因此撤销/重做只需还原计划，时间与冲突会一起恢复。

## 演示：主舞台采访延长 2 分钟

1. 点击主舞台「采访」行的时长 `6:00`，输入 `8`（即 8:00）回车；
2. 主舞台缓冲 `2:00 → 0:00` 自动消化超时，连线仍 ⚓ 10:15 准点；
3. 采访实际占到 10:07–10:15，与访谈间「嘉宾专访」（10:13 起）撞车 ——
   红色资源冲突横幅出现：资源「嘉宾-陈」、冲突区间 10:13–10:15、涉及两个场地的环节；
4. 横幅内给出可行建议，例如「『采访』缩短 2:00，10:13 前让出嘉宾-陈」
   或「在『嘉宾专访』前插入 2:00 垫片，推迟到 10:15 开始」——点击即可应用（可撤销）；
5. `↶ 撤销`（Ctrl/⌘+Z）后一切还原。

## 界面与操作

- **顶栏**：当前总时长（取各场地最晚结束，含与窗口的偏差）、收尾时刻、缓冲余量、
  可消化余量、固定点数、冲突数（固定点 + 资源）；撤销/重做/重置；
  播放头预演（1×/10×/60×/240× 倍速）；**锁定已执行前缀** / 解除锁定。
- **时间轴**：每个场地一条带，共用同一时刻刻度与播放头；⚓ 固定点、斜纹空档、
  红色固定点冲突区一目了然；资源冲突在独立的冲突道上按区间标出；已执行前缀加灰色遮罩。
- **流程单表格**：每个场地一张表。拖动 ⠿ 在本场地排序，或**拖到另一场地的表格**完成转场；
  点击时长修改（支持 `6:00` 或 `6` 分钟）；双击标题改名；🏷 编辑共享资源（逗号分隔）；
  📌 把当前开始时间设为固定开播点；行内 ＋ 插入、🗑 删除（均可撤销）。
  已执行环节显示 🔒，全部操作禁用。
- **快捷键**：空格 播放/暂停 · Ctrl/⌘+Z 撤销 · Ctrl/⌘+Shift+Z（或 Ctrl+Y）重做。
- 所有修改自动保存到浏览器 localStorage（含撤销栈与锁定状态），刷新后原样恢复；
  旧版单时间线数据自动迁移为双场地结构（包进主舞台）。

## 测试

`npm test` 覆盖：

- `src/engine/schedule.test.ts` — 单时间线回归：时间传播、缓冲→压缩的消化顺序与明细、
  压缩下限、固定点冲突、空档、多固定点分区消化、余量统计；
- `src/engine/multiSchedule.test.ts` — 双场地独立调整、固定点传播不跨场地、
  可压缩区段各自独立、已执行前缀（锁定集合推导、已执行环节不被消化、无解报冲突）；
- `src/engine/resources.test.ts` — 跨场地资源碰撞（冲突区间与涉及环节、相邻不算、
  同场地重叠归固定点冲突、传递重叠聚簇）、建议生成与模拟过滤（缩短/推迟/换场地、
  会被固定点反弹的方案不出现）、无解场景（双方锁定 → 建议为空）；
- `src/store/reducer.test.ts` — 撤销/重做、跨场地移动、已执行前缀的编辑禁令、
  APPLY_OPS 应用与整体拒绝、时长下限钳制、插入/删除；
- `src/store/persistence.test.ts` — 刷新恢复（含撤销栈与锁定）、v1 单时间线数据迁移、
  损坏数据回退；
- `src/engine/time.test.ts` — 时间格式化与解析。

## 目录结构

```
src/
  engine/schedule.ts       单场地调度引擎（纯函数）：顺延、消化、冲突、空档、已执行前缀锁定
  engine/resources.ts      跨场地资源冲突检测、可行调整建议（模拟验证）、状态操作
  engine/multiSchedule.ts  整档聚合：各场地排程 + 资源冲突与建议
  engine/time.ts           时间格式化与解析
  store/reducer.ts         快照式撤销/重做 + 全部修改动作（含跨场地移动与锁定守卫）
  store/defaultShow.ts     内置双场地 30 分钟节目单
  store/persistence.ts     localStorage 读写与 v1→v2 迁移
  hooks/usePlayhead.ts     播放头（倍速预演）
  components/              顶栏、时间轴、告警横幅（含建议按钮）、双场地流程单表格、环节行
```
