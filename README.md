# 直播导播流程单 · 双场地联排（Rundown Console）

面向直播导播团队的节目流程单。大型活动同时开**主舞台**与**访谈间**两条时间线：
两条线各自独立顺延、消化超时、保护固定开播点；但**嘉宾、主持人、转播车等共享资源
跨场地统一校验**——临时延长一个环节，既能看到本场地固定点如何消化，也能立刻看到
它与另一场地的资源碰撞区间、涉及环节与可行调整建议。系统不会把另一条时间线整体顺延。

技术栈：React 18 + TypeScript + Vite，无后端，数据保存在浏览器 localStorage。

## 运行方式

要求 Node.js ≥ 18。

```bash
npm install        # 安装依赖
npm run dev        # 开发预览（默认 http://localhost:5173）
npm test           # 运行全部测试（vitest，56 个）
npm run build      # 类型检查（tsc --noEmit）+ 生产构建（输出 dist/）
npm run preview    # 预览生产构建
```

## 双场地调度规则

1. **两条时间线独立顺延**：各场地环节紧跟本场地前一环节，调整只重排本场地。
2. **固定开播点不可越过（每场地各自保护）**：固定环节之前的超时，按顺序消化——
   先扣「上一个锚点（开播/已执行锁定行/上一个固定点）到本固定点之间」的**缓冲段**，
   再按流程顺序压缩**可压缩环节**（压到各自下限为止）；消化只发生在同一区段内，
   不跨固定点、不跨场地倒灌。消化不下 → 本场地红色固定点冲突，固定点仍在原时刻开播。
3. **共享资源跨场地统一校验**：环节可登记占用的人员/设备；同一资源在同一时刻只能被
   一个场地占用。碰撞报出**碰撞区间、涉及环节（含场地/固定/已执行标记）**，并给出
   经「变换后重排」模拟确认的**可行调整建议**：
   - 缩短先开始的一方（步进搜索可行边界，尊重压缩下限）；
   - 压缩前序缓冲/可压缩环节，把某一方整条**提前**；
   - 撑大前序缓冲（或插入缓冲段）把某一方**顺延**——若顺延会撞上后续固定点或其他
     资源占用，模拟会**否决**该建议，而不是把冲突一路推下去；
   - 移动固定开播点（前移/后移四个方向）；跨场地互换环节；
   - 涉及已执行锁定行时，唯一出口是**解锁已执行前缀**（一键操作，可撤销）。
   所有候选都被堵死时明确标注**无可行调整**及原因（固定点密集、撞压缩下限、前缀已锁定等）。
4. **已执行前缀锁定**：🔒 把某场地从头至指定环节锁定为「已按实际时刻执行」。锁定行是
   硬锚点：不被顺延、不被压缩、不可编辑/拖动/删除，且拦断消化区段——锁定之后的任何
   修改都不会倒灌进前缀。新环节、跨场地搬运只能落在未锁定后缀。
5. **空档**：固定点前内容不足时留出空档行（可插入内容），固定点依然准点。

计划时长与资源配置是唯一的源数据；压缩量、开始/结束时间、固定点冲突、资源碰撞、
调整建议全部由引擎实时推导，因此撤销/重做只需还原计划。

## 内置双场地节目单（10:00 开播，30 分钟窗口）

- **主舞台 A**：开场 → 新闻 → 采访·林澜（主持人+林澜）→ 缓冲 → ⚓10:15 转播车连线 →
  评论（主持人）→ 片尾
- **访谈间 B**：间场开场 → 对谈·周启 → 访谈缓冲 → 联合对谈（主持人+林澜+周启）→
  ⚓10:21 转播车访谈连线 → 收场
- 共享资源台账：主持人·苏眉、嘉宾·林澜、嘉宾·周启、转播车 1 号。

初始排布无碰撞。把「采访·林澜」延长 6 分钟即可看到：主舞台固定点 10:15 靠缓冲与压缩
保住，同时采访被压到 10:05–10:15，与访谈间 10:13 开始的联合对谈在 **10:13–10:15**
争抢主持人和林澜——横幅给出缩短等可行建议；简单顺延联合对谈会撞上主舞台评论，
因此该建议被明确标注不可行。

## 界面与操作

- **顶栏**：两场地最晚收尾与窗口偏差、收尾时刻、两场地缓冲/可消化余量、固定点数、
  已执行锁定段数、冲突数；撤销/重做/重置；播放头预演（1×/10×/60×/240×，同时扫两条线）。
- **共享资源台账**：登记/删除人员与设备（删除自动从环节解绑）。
- **场地列（×2）**：各自时间轴（固定点 ⚓、锁定 🔒、空档、冲突区、资源占用色点）
  与流程单表格。
- **拖动 ⠿**：同场地排序，或直接**跨场地搬运**到另一条时间线（落点自动避开已执行前缀）。
- **环节操作**：点时长修改（`6:00` 或 `6` 分钟）、双击改名、📌 设固定开播点、
  🔒 锁定到此为止的已执行前缀、👥 勾选占用的共享资源、插入/删除。
- **冲突横幅**：红色资源碰撞给出碰撞区间、双方环节与一组可一键采用的建议（记入撤销栈）；
  琥珀色横幅列出本场地为保固定点做的缓冲/压缩明细。
- **快捷键**：空格 播放/暂停 · Ctrl/⌘+Z 撤销 · Ctrl/⌘+Shift+Z（或 Ctrl+Y）重做。
- 所有修改（含撤销栈）自动保存到 localStorage（v2）；旧版单时间线 v1 数据会自动迁移
  到主舞台 A，刷新后原样恢复。

## 目录结构

```
src/
  engine/schedule.ts      单场地调度引擎（纯函数）：顺延、消化、冲突、空档、锁定锚点
  engine/resources.ts     跨场地资源碰撞检测 + 可行调整建议（变换后重排模拟裁决）
  engine/showSchedule.ts  双场地总调度：组合两场地结果与跨场地碰撞
  engine/time.ts          时间格式化与解析
  store/reducer.ts        快照式撤销/重做 + 全部动作（含跨场地、资源、前缀锁定、BATCH）
  store/defaultShow.ts    内置双场地节目单与原单场地节目单
  store/persistence.ts    localStorage v2 读写与 v1 迁移
  hooks/usePlayhead.ts    播放头（倍速预演）
  components/             顶栏、资源台账、告警横幅、场地列、场地时间轴、环节行
```
